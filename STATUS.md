# MAKERMAKER: status and technical notes

What is built, how, and what is planned. For users: [README.md](README.md). Goals and decisions: [GOAL.md](GOAL.md); terms: [CAD_DEFINITIONS.md](CAD_DEFINITIONS.md).

## Develop

```sh
npm install
npm run dev        # http://localhost:5173
npm test           # unit tests incl. geometry kernel in Node
npm run build      # typecheck + production build into dist/
npm run preview    # serve dist/ (service worker active, works offline after first load)
```

Chromium-based browsers only.

## Layout

- `src/doc` – document model (plain immutable data), expressions with units, undo history
- `src/kernel` – Replicad/OpenCascade build of bodies, runs in a Web Worker
- `src/viewer` – three.js viewport
- `src/ui` – panels
- `src/io` – `.mmk` design file (ZIP: `document.json`, `history/`, and `blobs/`: long texts such as imported files and pictures, each stored once), file access
- `public/sw.js` – offline cache

## PARAMOUNT, solve ASAP: everything from real geometry

Survey of 2026-11-07. The solid itself (OpenCascade) is exact for most features, and so are measuring and clash. What is not: what reaches it from the sketch (areas), what the view reads from its own triangles (0.05 mm by default, Settings → mesh detail 0.02–0.12, Float32) and then stores, a few kernel features, and the file formats with curves. Seen by the user: drawing on a cube's edge and zooming right in, shapes overlap it (a display offset, see Display).

**Rule.** Whatever is stored (sketch points, picked edges, planes, axes) and every value shown without `~` comes from the exact geometry. Hover may read triangles only where it gives the same answer as the click. The screen still draws triangles; that is fine.

**Why not ask the solid everywhere.** It lives in the worker: every question is a round trip (`truePoint` waits up to 1.5 s), the worker is busy rebuilding while a drag runs, exact queries (`BRepExtrema`, `BRepGProp`) are far slower than a ray on the triangles, and hover must answer within the frame (50–60 fps goal). Mesh bodies (STL, OBJ, 3MF, GLB, SKP), section and crossing lines and a failed build have no solid at all.

**Plan, in order.**
1. Fix the bugs found on the way (A); they are not approximations. Done.
2. Exact data with each build: the worker sends, with each body's mesh, its edges as line / circle / arc / ellipse / spline (centre, axis, radius, ends), each face as plane / cylinder / cone / sphere / free (its parameters), keyed by the mesh's face and edge groups, plus volume, area and box. Snaps, centres, axes, face planes, face size, the Info panel, align and box joint read these on the main thread, at once and exact; only free-form faces still need `truePoint` at the click. Built 2026-11-07 (`src/kernel/exact.ts`, `exact` with each mesh, by face and edge group, the faces and edges walked once by hash code: replicad's own lists compare each with all before it; bodies of over 20000 faces and mesh bodies have none and keep the triangles; the tight box only up to 1000 faces, beyond that the mesh's. A 7944-face STEP: 3.8 s more per build, its mesh 6.4 s): round edges' centres and axis picks (`axisAt`), round faces (`roundOfFace`: thread, bulge, push refusal), face picks on a plane (`picked`: sketch, work plane, section, cut placed on its exact plane; `flatFace`), the Info panel's volume, surface and box and the box align, move to object, box joint, pattern and joints read (`measure`; the box exact while the body's turn keeps the axes) read it. Still from triangles: face size and centre (`faceSize`, `faceCentre`), body edge snaps in sketches, picked fillet edges (step 3).
3. Store picked edges, faces and planes from that data, not from the mesh (B). Built 2026-11-07: picks on a kernel plane or cylinder lie on the true surface (`onSurface`: what `faceAt`, a step or a push looks up stays within its tolerance at any mesh detail; a pulled face moves by its normal's sign); picked fillet edges stored on the true curve (`truePolyline`); face centre and size from the kernel (centre of mass, area, a plane's normal and depth); sketch snaps on a curved body edge on its true circle (`onBodyEdge`), on an ellipse or free (spline) edge on its path: exact points with their directions, the cubic between two within 1e-6 mm of the edge (`EdgePath`, src/kernel/paths.ts; a curved edge's top in sketches likewise, `bodyCurveTop`; the 18 MB Raspberry Pi STEP, 7118 faces and 13983 free edges: 10.3 s meshed with all exact data); the measure tool takes the kernel's edge lengths and face areas first and says so when a field gets a mesh value; so does the Info panel for picked edges (length, a circle's Ø) and faces (area), with `~` only where the mesh stands in (a mesh body; areas above 1000 faces). A curved body edge's top in sketches on the kernel's circle (`roundSeg`, `bodyCircleAt`), a sketch circle's exactly; the extrude tool picks areas of overlapping shapes by their exact outlines (lined areas still by their triangles, 0.05 mm). A body turned off the axes: its box from its exact edges (`turnedBox`: ends and arcs' farthest points), where its faces are planes and cylinders and its edges lines and circles; else (spheres, fillets' tori, free-form) still the mesh's. A sketch on a section's cut face lies on the section plane itself (the picked and outlined planes are the true ones; only the clipping sits `eps` further in).
4. Sketch areas found on the true curves (C). Built 2026-11-07: areas closed by lines come from OpenCascade's splitter on the true curves and rounded corners (`lineFacesExact`, fuzzy 1e-3 mm; the JS face finder is gone); stored points keep 6 decimals in mm; `area`, `bounds`, `inside`, `edgeDistance`, `nesting`, a line's length and `pieces` work on the exact sides (`segments`: lines, true arcs, beziers, corner roundings and chamfers), so the Info panel shows a sketch shape's size, area and length without `~`. Corners beside a curved side: the circle r from both true sides (Newton), a chamfer its length along each curve; the kernel draws every shape with corners from these same sides (`segments`; replicad's own 2D fillet failed beside a bezier).
5. Curves through import and export (E); the kernel features (D). Done 2026-11-07 where it could be: SVG / DXF import and laser export keep arcs and cubics, the print check reads the solid, GLB / SketchUp weld at 1 µm, a curve's middle by length, coat's slab; kept with reasons: the thread (an exact helix cut fails in this OpenCascade), bulges (approximate by design), the joint sweep (no solid sweep along a turn).
6. Display: depth offsets in pixels, not mm (F). Done 2026-11-07: sketch outlines, area fills and section lines lie on their plane, in front by a depth offset (`FRONT` in src/viewer/sketch.ts), no longer 0.05 / 0.08 / 0.02 mm towards the viewer; outlines within 0.01 mm of their curves; the perspective camera's depth range follows the zoom. What is left in F is listed there.

**B. Stored or used as results, from triangles**
- Fillet / chamfer edges stored as mesh polylines (src/main.ts:342), matched in the kernel within 0.05 mm (src/kernel/build.ts:1079, 1148): a round edge's middle is up to the mesh detail off its chord; at detail ≥ 0.05 a fillet can lose its edge.
- `faceAt` (src/doc/pull.ts:23) eps 0.05 fixed: a click mid-facet on a cylinder at detail 0.12 finds no side (no sketch on it, a push instead of a resize); `rate` scales by the float dot product, not its sign (:41).
- Round faces (`roundOfFace`, src/viewer/viewer.ts:3501): axis from two vertex normals, circle through 3 Float32 vertices, length from vertices; feeds thread, bulge round, push refusal. Spanning < 5.7°: not round; > 0.8°: not flat; between: neither. `circleOf` (src/main.ts:2728, tol max(0.1, 2% r)) can take the wrong circle. Alt-picked: the thread starts at an arbitrary end.
- Axis picks on a round edge (`axisAt`, src/viewer/viewer.ts:1650): a circle fitted to segment starts and middles (middles one sagitta inside), tolerance 0.05: centre and Ø biased, and from about Ø 20 (detail 0.05) the fit fails and a straight edge is taken. Stored in joint axes, pattern around, revolve, rotate pivot, work plane and section axis, cut turn, draft hinge.
- Round-edge centre snaps (`edgeCentres`, :3052): the same fit, yet shown without `~` and used as exact by T, point-to-point, attach anchor, joint, work plane points (`truePoint` returns `about: false` for centres, :1592).
- Flat face plane: from one triangle normal and the hit point when the face is no extrusion end or side (`placeOn`, src/main.ts:200); flat means vertex normals within 0.8° (viewer.ts:854).
- Work plane on a face: origin from triangle centroids (`faceCentre`), x and hull from the mesh's smallest rectangle over its first 600 indices (`faceSize`, viewer.ts:1806); on a curved face: the hit triangle's plane. Draft hinge, bulge middle and half-size the same way.
- Cut, mirror, custom section from a face: the hit point and triangle normal (src/main.ts:1761, 2692, 5965); shell open faces and coat exclude too (:3170, 3524).
- Sketch on a section face: 1e-3 mm inside, the slider in steps of 1/1000 of the mesh bounds (viewer.ts:1443, 3730; src/ui/sections.ts:28).
- Mesh bounding box (`viewer.measure`, viewer.ts:3284): curved extremes short by up to a sagitta. Used by align (src/main.ts:4514), move to object (:1416, 1534), shell wall T (:1520), joint T and rest (:4686, 4788), box joint touch test and finger count (:3627, 3659), pattern box (:2486), and `cad.measure` whenever the kernel returns null, silently (:7631).
- Measure into a field: a rejected kernel length silently hands over the segment sum (src/main.ts:3904); face length falls back to the mesh without `~` (:3921); face L/B orientation from mesh edges (:3820).
- Sketch snaps on body edges: a curved one put on the circle through 3 mesh vertices (src/viewer/sketch.ts:1132–1143), wrong for ellipses and splines; a curved edge's top from its extreme vertex (`roundSeg`, :1024); stored as sketch points.
- Extrude area pick on area triangles at 0.05 (src/viewer/extrude.ts:432, build.ts:350): within 0.05 of an arc a click takes the neighbour or nothing.

**D. Kernel features (src/kernel/build.ts)**
- Thread (modeled): cut after unbaked fillets and chamfers (2026-11-07: an edge rule such as Vertical took the groove's ~300 edges, failed and then filled it with tiny fillets). Flat triangles, 36 steps per turn: sag ≈ 0.0038·R (M10: 0.02 mm), thousands of faces, heavy STEP and booleans. Kept: an exact sweep along `makeHelix` (`genericSweep`, Frenet) was tried 2026-11-07 and this OpenCascade build cuts it wrongly: an M10 inside thread cut nothing, an M20 × 30 emptied the body, an M6 × 0.5 came out invalid after 37 s.

- Bulge on a round face: 41 samples fitted by a B-spline, the peak rounded off. Approximate by design, staying so.
- Cut moving along a joint, and joint clash: curved faces stamped every 3° / 1 mm, at most 60: ridges (hinge R100 with r 5: ~0.7 mm); clash's first contact snapped to those steps. Open: OpenCascade sweeps no solid along a turn; finer steps cost a boolean each.
- Coat with excluded faces: done 2026-11-07: the slab sized from points at most its margin apart along the edges (was 5 per edge: a lip on large arcs).
- Measure: done 2026-11-07: a curve's middle lies half its length along it (was the point nearest the mesh guess).

## Status

- Bodies are recipes of extrude steps: each has a sketch plane (ground / front / right plane with offset, or the top face of an earlier step), one or more profiles (rectangle with corner radius, circle, regular polygon, polygon) or picked areas, a depth, how far it also reaches behind its plane (back) and add / cut (cut: blind or through). Features run in order, except fillets/chamfers: unbaked they run last, so they also round or chamfer edges of later cuts (their edges draw light grey). Bake (button on the card) keeps one where it is: later cuts go through it (hatched card, dark edges). Click a fillet/chamfer face to pick that part (double-click: the whole finish); Del leaves that edge out (Restore on the card brings it back) or deletes the whole finish.
- Sketch mode: New sketch (S or the toolbar's first tool) picks a top face or empty space, turns the camera to it and shows a grid; leaving the first pull of a direct shape flat (click or Esc) also enters it; Draw on a selected sketch reopens it. In sketch mode R / C / P draw flat into the sketch and the tool goes on; Esc stops the tool, Esc again or ✓ leaves. E in sketch mode turns a flat view to an angled one with its selected shapes, or all of them, picked (see Extrude below), the sketch's areas shown faintly. Areas: overlapping shapes split into pieces, computed exactly by the kernel; where lines take part, the faces they enclose with the shapes they reach: ends sticking out are ignored, a line's end on a curve (a tangent off a circle, say) meets it where it was drawn although curves are flattened there (`withEnds`), a line across splits a face, curves there become fine polylines, see `src/doc/arrangement.ts`; an extrusion stays linked to its areas (stored as inside / outside shapes, or for line faces as a point inside, so they follow shape edits). E on a sketch with lines pulls all its areas.
- A drawing tool shows its current mode top left when it starts and when the mode changes, with how to change it ("Change with C or Alt"), for 3 s.
- Drawing modes (`MODES` in src/viewer/sketch.ts): rectangle: two corners, from the centre, turned (a side's two ends, then its width), turned from the centre (its middle, a point it points to, then its size; Alt: ⇄ turned); circle: centre and radius, two points across, through three points, tangent to two lines (click both, then where it lies: its size; typed: its radius, R); regular polygon: centre to a corner, centre to a side's middle, one side end to end (the polygon to its left). Alt (Shift Alt: back) steps to the next mode: before drawing it is kept for the shapes to come, while drawing it is for that shape only (its first point stays); so does the tool's key or toolbar button pressed again (kept). A only splits lines for snapping. The mode is remembered this session; a switch shows its pictogram and name top left in the view for a second; the hint names the mode. Tangent circle: the line a click would take lights orange (one in the sketch's plane first; snap points do not hide it, kept guides count), the picked ones stay lit; a line along the first is refused. Then a dashed bisector appears: the middle rides on it, the radius on the zoom's step; it snaps and crosses like a guide (G keeps it as one).
- Direct tools: R rectangle, C circle (cylinder), N regular polygon (diameter, Tab: number of sides; the first corner points at the pointer), L line (its modes below; a line extrudes as the edge of a face lines enclose, or once closed), O sphere (drag from its centre on a face or the ground). Shapes keep their meaning (a hexagon stays a regular polygon with 6 sides). Drawing tools and Extrude stay on after each shape or pull until Esc; one-shot actions (look at face and the like) end by themselves.
- Line tool (L; `line` in `MODES`, src/viewer/sketch.ts; the Polygon tool and P are gone, and so is ⌘ to go on from the last line): Alt (Shift Alt: back) or L again steps through its modes, before a line or in the middle of one, each side in the mode at that moment: **one line per two clicks** (the third starts a new one anywhere; in the middle of a line: its last side, then it ends), **free polygon**, **bezier** (every point is a bezier point: a click: smooth, its handles along the line between its neighbours, set when the next point comes; press and drag: both handles mirrored as pulled; Shift: the handle in angle steps; a double-click on a point afterwards makes it sharp; the first handle on from a line or arc lies along it), **arc** (round, tangent to what comes before: one click each; a line's first: start, end, then the bulge; typed: radius, Tab, angle). Enter, Esc or a double-click finish a line open (Enter after a typed value sets that point first; with one point nothing is kept); a click on its start closes it into a shape (it snaps there; pulled like any shape, smooth through the start if the first handle was pulled); Backspace takes the last point back. D during a line measures its length or radius.
- Tangent from a curve (line tool, one-line and polygon modes; `tangentFrom` in src/viewer/shapes.ts, `curveOf` in src/viewer/sketch.ts): a plain click on a circle or curve is a plain point; with Ctrl (role Tangent in `MODS`) the pointer on a sketch circle, arc or bezier side or a body's round edge says so, and a click, or a right click without it, starts a line whose start slides along the curve so it stays tangent while the pointer moves; the next click sets its end (angle steps, a typed angle or length and snaps stay tangent where the curve runs that way). The point clicked picks which tangent, if there are several. Where none reaches (inside a circle, beyond a short arc's end) the start stays and the line runs along the curve there. A way to draw, no lasting link: moving the curve later leaves the line.
- Curved sides: `curves` on polygons and lines (schema unchanged, optional), per side null, `{c1, c2}` (bezier handles) or `{mid}` (an arc through it), as real curves in the kernel (replicad's `cubicBezierCurveTo`, `threePointsArcTo`), so STEP keeps them. Where points are enough they are flattened (32 pieces a side: `flattened`, `sidesOf` in src/doc/profiles.ts): outlines, inside, area, bounds, snapping, laser cuts. Lines meeting end to end, curves included, become one exact closed shape (`closedLoop`). Lines crossing a curve in its middle (or a circle) find their faces on those pieces, each piece remembering where along its curve it lies, and the face is built from true curves: the part of the bezier curve (blossoming), of the arc or the circle's quarter. Snap points on curves: ends, middle (A / Shift A: more or fewer, evenly by length), arc centres, crossings. Extrude, Revolve, Loft, Sweep (profile and path), Cut along a line (exact; moved aside by an offset: in pieces), Mirror, Copy, Move, Turn and resize take them; `cad.polygon` and `cad.line` take `curves`. Not yet: Sketch Offset (it says so), corner radius (the field hides), a curved shape's sides pushed through its body's face (a flat face gets a Push / pull step instead), round-edge rules for arcs.
- An arc's middle (a handle, on its two radii; `centreMoved` in src/viewer/shapes.ts) moves the only way the tangents allow: arc smooth at its start: along the normal there, the angle kept, its end and what follows moving; else smooth at its end: the same from there; neither: square to its chord, both ends staying. Dragged on the zoom's step; clicked it follows the pointer and takes a typed diameter until a click or Enter (Esc: back). A selected line or polygon lists its arcs' diameters in the side panel (Ø and the side's number), typed or scrubbed, moving the same way; a free arc cannot get narrower than the distance between its ends. Drawing an arc also takes its diameter, Ø in the pointer's note.
- Sides keep their formulas (`sizes` on lines and polygons, `src/doc/sizes.ts`): what was typed for a side while drawing (length, angle, an arc's diameter) or in its panel field stays as an expression, and when a parameter changes (`followSizes`, run by the history) the points are worked out again side after side, as if dragged there. Dragging or resizing keeps a formula as `+ delta`; an angle no longer right is dropped. What follows a changed side moves along rigidly; a polygon's last point stays, so a rectangle stays one. An arc tangent at both ends between straight sides acts like a fillet: its ends slide along both sides, as far as they reach. A point moved keeps every tangent there was (`tangentsHeld` in src/viewer/shapes.ts): arcs are made anew from the tangent they keep, on along arcs that run on smoothly, ends sliding along a straight side next. These help lines and dots are violet and show only with the pointer tool, on the line or polygon under the pointer in the open sketch group (selected or not).
- Editing points (the polygon or line hovered, `pointHandles`, `pointMoved`, `controlMoved`, `smoothToggled` in src/viewer/shapes.ts): every point and curve handle drags, snapping to other shapes' points, else the zoom's step (Ctrl: the minimum; Shift: a bezier handle in angle steps). A point takes its bezier handles along; an arc beside it keeps its shape. A handle at a smooth point turns the one across it, keeping its length. A double-click on a point: smooth to sharp and back (read from the shape, no flag: handles in line are smooth; arcs stay arcs; straight sides become bezier curves when made smooth). A clicked bezier handle follows the pointer and takes a typed length, Tab its angle (from the sketch's X). A straight line of two points (`simpleLine`) has no box handles, its two points show as long as it is selected; its reference mark stays.
- Bodies have a colour (picker in the body panel, swatch in the list; new bodies get one from a palette) and an eye to show / hide them like sketches (Shift-click another eye in the same list: every row between, both included, goes the way the first click went; in sketch mode the same for see-through / fully shown); hidden bodies are still built but not drawn, picked or snapped to.
- Snapping while drawing: corners and line ends, centres, the middles of sides and straight edges, circle quadrants, crossings of sketch lines, circles and body edges, then along lines and edges, else on the zoom's step; only geometry in the plane drawn on. A sketch takes the pointer when it is over one of its shapes or near an outline; empty space draws on the ground unless it is seen almost edge-on. A note next to the pointer says what it snaps to (along a side with the lengths on both sides); the shape, line or edges it belongs to light up. With the pointer on a line, A adds an evenly spaced snap point along it (around a circle: one more than the 4 quadrants), Shift A removes one; while changing, all its points show.
- Lines that close a loop (the new line's ends meet other lines' ends, within 0.001 mm, either way round) become one polygon, which extrudes like any shape.
- Line tool: holding ⌘ (else Ctrl) after a line starts the next one at its end at once, shown, snapped and typed into like the first (it stays when ⌘ is let go, to type; Esc drops it; ⌘ as part of a shortcut like ⌘Z does not start it); a click still holding ⌘ goes on from the new end.
- The angle counts from the previous line (going straight on is 0°), else from the plane's x axis; B with the pointer on a straight line, edge or guide counts it from that line instead (again, or off a line: from the x axis); the hint shows on a line.
- Lines and polygon sides are drawn as angle and length from the last corner: the angle turns in 1° steps (Ctrl: the minimum angle, Settings → General, default 0.01°; Shift: the angle step, default 45°, A finer, Shift A coarser, through 90, 45, 30, 15, 10, 5, 1°, set before pressing Shift; rays around the last corner preview its directions), the length on the zoom's step (Ctrl: the minimum step). A snap point or line sets the end exactly (with Shift, or a typed angle, its distance along that angle). The pointer's note shows the length (L) first; the angle (∠) is labelled inside the angle, between a faint ray along the plane's x axis and the side with an arc between them, as close as it stays clear of the other labels, the lines, the pointer and its note and the view's controls, else just outside the angle: typing a digit starts the length, Tab switches to the angle, a typed value stays while the pointer sets the other, click or Enter sets the corner.
- Modifiers, one meaning each (`MODS` in src/ui/keys.ts, listed in Settings → Hotkeys). At a click: Shift adds to the selection or takes away (lists: a range), ⌘ (else Ctrl) adds one in lists, isolates on an eye and goes on with the line tool, Alt picks faces and edges. ## CAD goals

What a basic, fully working CAD tool still needs, most important first (revolve, loft, sweep, shell, mirror, pattern, linked copies, threads, rotation, work planes and STEP export are built, 2026-11-02).

1. **Dimensions and basic constraints** (fixed length, parallel, perpendicular, equal, coincident): truly parametric sketches.
2. **Measure the angle** between two things (Distance measure gives distances); the Info panel measures one thing.
3. **Holes as a feature** (counterbore, countersink) and a **2D drawing / PDF** of a part.
4. **Rotation rings** on the move gizmo.
5. **Flatten** a body (its whole recipe as one fixed solid, kept as STEP data; booleans' tool bodies can go then; lossy, only ⌘Z undoes it).
6. **Any body as a cutter** in the Cut tool (now: planes, sketch lines and shapes, balls, cylinders).

- **Custom origin picker**, for later if needed: a 3D picker (corner, plane or point, moved and turned like an object) for groups and objects, turned with the group, moved by joints. To check first: whether drawing on moved joint parts or rotated groups already gets what it would give.
- **Cross browser**: usable in Firefox and Safari too, with the drawbacks being file handling (no saving in place, no script folder: downloads and uploads instead).
- **Drawings**: sheets with live views at several scales, title block, multipage, vector PDF and SVG. The plan: DRAWINGS.md.

Collected from [GOAL.md](GOAL.md) and the design talks; roughly in the order they were asked for.

- **Move along any direction**: move objects not only along X / Y / Z but parallel to any edge, line or work plane (picked as the direction).
- **Undo history list**: ⌘Z twice shows the latest steps; drag a line through the log to move in history.
- **Render quality target**: renders stop at a chosen quality (say 80 %) and save the picture; raising it to 100 % continues the render (or renders again, whichever the path tracer allows).
- **Real light units** (stretch goal): for now glow strength and the sun are made-up numbers. Real ones: a glow's light in lumens (candela = lm / 4π, 1 / distance², not tied to the body's size, × 10⁶ as the scene is in mm), the sun and sky in lux, and an exposure like a camera's, the same in the 3D view and renders.
- **Nicer renders**: materials and lighting choices for the path traced render, Mitsuba 3 through a local helper (deferred); screenshot turntable and dolly clips.
- **Laser export, nesting**: several parts laid out on one sheet (face choice, DXF and kerf are built).
- **Imports**: meshes in booleans and exports; DXF blocks (INSERT) and SVG text. Maybe use [cadmpeg](https://github.com/cadmpeg/cadmpeg)
- **Materials, further**: sheet thickness (left out for now): a value expressions can use, a change resizes linked geometry, mismatches shown; shadows from the sun in the 3D view.
- **Recovery copy**: a copy in the browser's storage a moment after each change, offered when the app starts after a crash or power cut (the close warning only covers closing and reloading).
- **GUI through the commands**: a tool's final step (when the user confirms) calls its command in src/api/commands.ts; hover, picking, previews and live scrubbing stay in the UI. New features from the start, old tools when reworked anyway, all before LLM or Python control. Photo spheres and light have no commands yet.
- **Import options panel**: the unit dialog is not styled or placed like the other floating panels.
- **Joints, further**: a fixed joint, limits enforced while dragging, joints solved against each other (now each joint only places its own children).
- **Linked copies, further**: linked sketches (shapes shared, placed apart) and linked groups as one unit.
- **Cutters, further**: one cutter cutting several bodies, an editing mode that reveals hidden cutters, a note when a cutter removes nothing.
- **Face edits**: moving faces that no extrusion made (fillet, boolean and sphere faces).
- **Drawings**: paper sheets with scaled views, dimensions, sections, PDF export.
- **Views, further**: editing in every view (now in the main one; ⇄ swaps a view in), views saved with the design, a fixed quad layout.
- **incase**: the sibling project ../incase should be included here.
- **Rotating in the 3D view** as in incase.
- **Render camera**: change the field of view for renders, set it as real-life camera focal length in mm, and a default field of view in the settings.
- **Threads, further**: special threads (ball screws, ACME / trapezoidal, the Deckel thread of Munich, pipe threads), left-hand threads (ISO metric and UNC / UNF are built); special geometry that is always modelled, built so that e.g. the top edge of a threaded hole or cylinder can still be chamfered.
- **Joints, clamping positions**: named positions a joint snaps to.
- **Mesh to CAD model**: a button that turns a mesh into a CAD model, like [this video](https://youtu.be/meBi616y1mg) shows ([ScanRuler](https://github.com/CNCKitchen/ScanRuler) by CNC Kitchen).
- **Command API, further**: more commands (every tool: loft, revolve, sweep, draft, bulge, patterns, joints, work planes, exports …) and the GUI's own actions going through it (built: the command table in src/api/commands.ts and `window.makermaker`).
- **LLM control**: an API through which an LLM can control everything.
- **Desktop wrapper** (Tauri / Electron) with native file access.
> prompt fort iamge to svg conversions:
```text
Create a **simple, scale-accurate 2D SVG** from the attached reference image for import into CAD / 3D software.

Use **only the attached image**. Do **not** search online, use datasheets, or add dimensions from external knowledge.

The goal is **mechanical reference geometry**, not visual reproduction.

Requirements:

- Use the alrgest dimensions explicitly shown in the image as the primary scale reference.
- Infer all other dimensions proportionally from the image.
- Keep everything in **metric millimetres**.
- Make the SVG physically scaled so that CAD software imports it at the intended real-world size.
- Use simple black outlines on a white background.
- No shading, textures, perspective, decorative detail, dimension arrows, or photographic detail.
- Use as **few SVG objects as practical**.

Prioritize these features:

- overall outer dimensions
- outline/profile of the main object
- corner radii
- mounting holes
- screw-hole locations
- pin/header locations
- repeated hole or pin spacing
- connectors, switches, sockets, and other parts protruding beyond the main body
- other mechanically important features

For repeated pins, pads, holes, or headers:
- detect whether they appear to use a regular raster/pitch
- infer that pitch from the drawing where possible
- preserve the correct number and approximate locations
- if a standard-looking pitch can be inferred directly from the image, note the estimated pitch, for example `~2.54 mm`

For mounting holes:
- include their estimated diameter and centre positions
- note the corresponding **metric screw size**
- if the screw size is explicitly stated in the original drawing, reproduce it normally, e.g. `M3`
- if it is only inferred from the image, mark it clearly as approximate, e.g. `~M3`, `~M2.5`, etc.
- never present an inferred screw size as exact

For connectors or components that stick out beyond the main outline:
- make them separate SVG objects
- simplify each one to a rectangle, rounded rectangle, circle, or similarly basic shape
- do not draw internal connector details unless mechanically necessary

For pins and labels:
- label only the most important pins/functions if they are clearly readable or inferable from the supplied image itself
- do not invent pin functions
- keep labels in a separate SVG group so they can easily be removed before CAD import

Accuracy rules:

- Clearly distinguish between:
  - dimensions explicitly shown in the image
  - dimensions estimated proportionally
  - dimensions inferred from repeated geometry/pitch
- Do not silently use outside knowledge.
- If something is uncertain, make a reasonable proportional estimate rather than omitting it.
- Prefer mechanically useful approximate geometry over visual detail.

SVG construction:

- Position of the drawn lines are identically placed relative to the image boundaries as on the original image
- The SVG artboard has the same proportions as the original image
- output a **real SVG file directly**, not a raster image
- use millimetres for width/height where possible
- use a matching `viewBox`
- give important objects sensible IDs such as:
  - `main-outline`
  - `mounting-holes`
  - `header`
  - `usb-port`
  - `power-port`
- group optional text labels separately
- keep the SVG clean and easy to edit

Also provide a short note listing:
- the dimensions taken directly from the image
- the most important estimated dimensions
- estimated raster/pitch values
- estimated mounting screw sizes, using `~M3` style notation wherever they were not explicitly specified

The final result should look like a **minimal mechanical CAD tracing**, not like the original photograph or product illustration.
```

### Design notes

- Shift does the opposite of a tool where that makes sense.
- Editing 2D and 3D objects uses the same tools wherever possible (booleans work on both, for example). There is no special sketch mode: sketches can be drawn at any time. Sketch objects are then grouped like 3D objects: plain groups of sketch objects instead of a separate sketch container. How they get grouped automatically is still to be decided.
